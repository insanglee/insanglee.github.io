Reading Questions

Fellegi-Sunter Model

The Fellegi-Sunter model estimates the probability structure of agreement patterns for true matches and non-matches, using quantities such as the m- and u-probabilities to construct a likelihood-based match score. Unlike the workshop’s fixed weighted score, it estimates linkage uncertainty from the data rather than assigning similarity weights only by rule.

Unique IDs

Records with a reliable unique identifier can be linked directly because the identifier unambiguously determines whether two records belong to the same entity. Records without such an identifier require probabilistic linkage because names and other identifying fields may contain missing values, spelling errors, or measurement error, making the match uncertain.

Data-Generating Process

The workshop simulates two administrative files, TRS and TEA, with 500 records each. The first 100 TEA records are generated as true matches to the first 100 TRS records. The baseline simulation corrupts 20% of those true matches by changing a first name, introducing a last-name typo, or shifting a date of birth by one day. I retained set.seed(42) for reproducibility.

Corruption-Rate Sensitivity

run_corruption_test <- function(rate) {

  set.seed(42)

  trs <- create_trs_data(500)
  tea <- create_tea_data(
    trs,
    n = 500,
    num_matches = 100,
    corruption_rate = rate
  )

  validation <- create_validation_set(trs, tea)

  trs_c <- trs %>%
    mutate(
      first_name_std = standardize_names(first_name),
      last_name_std = standardize_names(last_name),
      first_initial = substr(first_name_std, 1, 1),
      dob_std = standardize_date(dob)
    )

  tea_c <- tea %>%
    mutate(
      first_name_std = standardize_names(first_name),
      last_name_std = standardize_names(last_name),
      first_initial = substr(first_name_std, 1, 1),
      dob_std = standardize_date(dob)
    )

  det <- deterministic_linkage(trs_c, tea_c)

  ua <- det$remaining_a
  ub <- det$remaining_b

  last_sim <- calculate_similarity_efficient(
    ua$last_name_std, ub$last_name_std
  )

  first_sim <- calculate_similarity_efficient(
    ua$first_name_std, ub$first_name_std
  )

  dob_sim2 <- outer(
    as.numeric(ua$dob_std),
    as.numeric(ub$dob_std),
    function(x, y) {
      d <- abs(x - y)
      ifelse(d == 0, 1, ifelse(d == 1, 0.95, 0))
    }
  )

  comparisons <- expand_grid(
    idx_a = 1:nrow(ua),
    idx_b = 1:nrow(ub)
  ) %>%
    mutate(
      record_id_a = ua$record_id[idx_a],
      record_id_b = ub$record_id[idx_b],
      last_name_sim = sapply(
        1:n(),
        function(k) last_sim[idx_a[k], idx_b[k]]
      ),
      first_name_sim = sapply(
        1:n(),
        function(k) first_sim[idx_a[k], idx_b[k]]
      ),
      dob_sim = sapply(
        1:n(),
        function(k) dob_sim2[idx_a[k], idx_b[k]]
      ),
      match_score =
        0.40 * last_name_sim +
        0.30 * first_name_sim +
        0.30 * dob_sim
    )

  prob_links <- comparisons %>%
    filter(match_score > 0.95)

  combined <- bind_rows(
    det$matches %>%
      transmute(
        trs_record_id = record_id_a,
        tea_record_id = record_id_b,
        match_score = 0.99
      ),
    prob_links %>%
      transmute(
        trs_record_id = record_id_a,
        tea_record_id = record_id_b,
        match_score = match_score
      )
  )

  quality <- assess_linkage_quality(combined, validation)

  tibble(
    corruption_rate = rate,
    rule1 = det$summary$Matches[1],
    rule2 = det$summary$Matches[2],
    rule3 = det$summary$Matches[3],
    probabilistic = nrow(prob_links),
    precision = quality$metrics$Value[
      quality$metrics$Metric == "Precision"
    ],
    recall = quality$metrics$Value[
      quality$metrics$Metric == "Recall"
    ],
    f1 = quality$metrics$Value[
      quality$metrics$Metric == "F1-Score"
    ]
  )
}

Answer-Key Sensitivity

The workshop sensitivity function evaluates only the probabilistic candidate pairs even though most true matches have already been recovered by deterministic rules. I therefore compared the original sensitivity results with a complete evaluation that retains deterministic matches and evaluates decisions against the complete 500 × 500 pair universe. Because the supplied validation set contains only the 100 known positive matches, I expanded the evaluation to all 500 × 500 possible record pairs and treated every pair not listed in the validation set as a non-match.

sensitivity_old <- sensitivity_results

sensitivity_analysis_complete <- function(
    all_comparisons,
    det_result,
    validation_set) {

  thresholds <- seq(0.70, 0.99, by = 0.05)
  results <- tibble()

  for (threshold in thresholds) {

    prob_matches <- all_comparisons %>%
      filter(match_score >= threshold) %>%
      transmute(
        trs_record_id = record_id_a,
        tea_record_id = record_id_b
      )

    det_matches <- det_result$matches %>%
      transmute(
        trs_record_id = record_id_a,
        tea_record_id = record_id_b
      )

    test_matches <- bind_rows(
      det_matches,
      prob_matches
    ) %>%
      distinct()

    answer_key <- expand_grid(
      trs_record_id = trs_data$record_id,
      tea_record_id = tea_data$record_id
    ) %>%
      mutate(
        true_match = if_else(
          paste(trs_record_id, tea_record_id) %in%
            paste(
              validation_set$trs_record_id,
              validation_set$tea_record_id
            ),
          1L, 0L
        )
      ) %>%
      left_join(
        test_matches %>% mutate(our_match = 1L),
        by = c("trs_record_id", "tea_record_id")
      ) %>%
      mutate(
        our_match = replace_na(our_match, 0L)
      )

    tp <- sum(
      answer_key$true_match == 1 &
        answer_key$our_match == 1
    )
    fp <- sum(
      answer_key$true_match == 0 &
        answer_key$our_match == 1
    )
    fn <- sum(
      answer_key$true_match == 1 &
        answer_key$our_match == 0
    )

    precision <- if (tp + fp > 0) tp / (tp + fp) else 0
    recall <- if (tp + fn > 0) tp / (tp + fn) else 0
    f1 <- if (precision + recall > 0) {
      2 * precision * recall / (precision + recall)
    } else {
      0
    }

    results <- bind_rows(
      results,
      tibble(
        threshold = threshold,
        num_matches = nrow(test_matches),
        precision = precision,
        recall = recall,
        f1 = f1
      )
    )
  }

  results
}

Data-Based Weights

The workshop used fixed weights of 0.40 for last name, 0.30 for first name, and 0.30 for date of birth. I instead estimated agreement probabilities from the full pair universe. Because zero agreement probabilities would make log(m/u) infinite, I used Jeffreys smoothing (+0.5) before calculating the log ratios.

weight_pairs_full <- expand_grid(
  idx_a = 1:nrow(trs_clean),
  idx_b = 1:nrow(tea_clean)
) %>%
  mutate(
    record_id_a = trs_clean$record_id[idx_a],
    record_id_b = tea_clean$record_id[idx_b],
    last_agree = as.integer(
      trs_clean$last_name_std[idx_a] ==
        tea_clean$last_name_std[idx_b]
    ),
    first_agree = as.integer(
      trs_clean$first_name_std[idx_a] ==
        tea_clean$first_name_std[idx_b]
    ),
    dob_agree = as.integer(
      trs_clean$dob_std[idx_a] ==
        tea_clean$dob_std[idx_b]
    ),
    is_true_match =
      paste(record_id_a, record_id_b) %in%
      paste(
        validation_set$trs_record_id,
        validation_set$tea_record_id
      )
  )

estimate_mu <- function(x, true_match) {

  x_true <- x[true_match]
  x_false <- x[!true_match]

  m <- (sum(x_true) + 0.5) /
    (length(x_true) + 1)

  u <- (sum(x_false) + 0.5) /
    (length(x_false) + 1)

  c(m = m, u = u)
}

mu_last <- estimate_mu(
  weight_pairs_full$last_agree,
  weight_pairs_full$is_true_match
)

mu_first <- estimate_mu(
  weight_pairs_full$first_agree,
  weight_pairs_full$is_true_match
)

mu_dob <- estimate_mu(
  weight_pairs_full$dob_agree,
  weight_pairs_full$is_true_match
)

mu_table_full <- tibble(

Review Band

I defined the manual-review band as scores from 0.85 up to, but not including, the selected 0.89 automatic-link threshold. I retained 0.85 as the lower bound for comparability with the workshop and used 0.89 as the upper bound because pairs at or above 0.89 were automatically linked; pairs below 0.85 were treated as having insufficient evidence to justify manual review.

make_diagnostic_set <- function(threshold) {

  prob_links <- weighted_comparisons %>%
    filter(data_based_score >= threshold) %>%
    transmute(
      trs_record_id = record_id_a,
      tea_record_id = record_id_b,
      match_score = data_based_score,
      last_name_sim,
      first_name_sim,
      dob_sim
    )

  det_links <- det_result$matches %>%
    transmute(
      trs_record_id = record_id_a,
      tea_record_id = record_id_b,
      match_score = confidence
    )

  predicted_pairs <- bind_rows(
    det_links %>% select(trs_record_id, tea_record_id, match_score),
    prob_links %>% select(trs_record_id, tea_record_id, match_score)
  ) %>%
    distinct(trs_record_id, tea_record_id, .keep_all = TRUE)

  list(
    prob_links = prob_links,
    predicted_pairs = predicted_pairs
  )
}

Report

This analysis asks a simple administrative-data question: how many people appear in both the simulated TRS and TEA files, and how confidently can the two records be treated as belonging to the same person? The files contain 500 records each, and the simulation provides a known answer key with 100 true cross-file matches. That answer key makes direct evaluation possible, although such certainty would rarely exist in a real administrative-data project.

I began with the workshop’s deterministic rules. The strictest rule required exact agreement on last name, first name, and date of birth. Two additional rules allowed a first initial or a one-day difference in date of birth. Under the baseline 20% corruption setting, the deterministic rules recovered 93 of the 100 true matches with no false positives. The probabilistic stage then evaluated the remaining records using partial similarity on last name, first name, and date of birth. The probabilistic step recovered the seven remaining true matches and added no false matches under the final specification.

Changing the data-generating process showed how linkage performance depends on data quality. At 10% corruption, recall was 0.99 and F1 was 0.995. At 40% corruption, recall fell to 0.93 and F1 to 0.964, while precision remained 1.00. Exact Rule 1 matches dropped from 90 to 60 as corruption increased. The largest practical effect of noisier identifiers in this simulation was therefore a loss of recall: true matches became harder to recover, even though the algorithm continued to avoid incorrect links.

I also corrected the workshop sensitivity evaluation. The supplied validation set contains the 100 known positive matches, while the workshop shortcut evaluates only the probabilistic candidate pairs after deterministic matches have been removed. I therefore expanded the evaluation to the full 500 × 500 pair universe, treating all pairs not listed in the validation set as non-matches. When deterministic and probabilistic decisions were evaluated together, recall increased by 0.93 at each tested workshop threshold. This matters because an evaluation that ignores records already linked deterministically can make a successful linkage procedure appear to have very low recall.

Blocking on the first letter of standardized last name reduced the probabilistic candidate set from 165,649 pairs to 19,030, an 88.51% reduction. All seven true matches entering the probabilistic stage remained reachable, so this blocking rule improved computational efficiency without lowering recall in this simulation. However, blocking is still a substantive restriction: if a true pair had different first letters after corruption or standardization, it would become impossible to recover regardless of its later similarity score.

I replaced the workshop’s fixed 0.40/0.30/0.30 weights with weights based on estimated agreement probabilities. After Jeffreys smoothing, the raw log(m/u) values were normalized to sum to one so that the weighted score stayed on the 0–1 scale. The resulting weights were approximately 0.176 for last name, 0.181 for first name, and 0.644 for date of birth. DOB received the greatest weight because exact DOB agreement was common among true matches but extremely rare among non-matches.

Using these weights, I evaluated thresholds from 0.70 to 0.99. The first threshold that achieved precision = 1.00, recall = 1.00, and F1 = 1.00 was 0.89, so I selected 0.89 as the final automatic-link threshold. I prioritized F1 because both error types matter for the study question. A false positive joins records from different people and can inflate the estimated overlap or attach one person’s information to another. A false negative omits a person who truly appears in both systems and biases the overlap count downward. The review band was set from 0.85 to below 0.89; it contained two pairs, and neither was a true match.

At the chosen threshold, the final linkage produced 100 true positives, 0 false positives, and 0 false negatives, so the estimated TRS–TEA overlap is exactly 100 in this simulation. The absence of errors at the chosen threshold also means that the assignment’s request for ten false positives and ten false negatives cannot literally be satisfied without inventing cases. I therefore report that none exist at 0.89 and use alternative thresholds only as supplementary diagnostics to illustrate the types of errors that would occur if the policy were made more permissive or more restrictive.

The perfect final score should not be generalized to real administrative data. The same simulated answer key was used to estimate data-based weights, choose the threshold, and evaluate final performance, so the result is optimistic. If the answer key itself contained mistakes, then the estimated m and u probabilities, field weights, threshold curve, and reported precision and recall could all shift. Conclusions would remain credible only if the key correctly identified the true cross-file matches and if pairs not listed in the key were truly non-matches. Real files can also contain missing identifiers, multiple errors in the same record, duplicate people, name changes, and demographic groups with systematically different rates of common names or data-entry error. Those groups could be linked less reliably and could therefore be over- or under-represented in downstream counts. A linked file should therefore be treated as a documented claim about identity, not as error-free ground truth.

Data Note

The data are simulated administrative records generated by record_linkage_workshop.R with set.seed(42). The analysis uses TRS and TEA files with 500 records each and evaluates corruption rates of 0.10, 0.20, and 0.40. The final method combines three deterministic rules, blocking on the first letter of standardized last name, data-based field weights, and an automatic-link threshold of 0.89. The known answer key contains 100 simulated true matches.

The simulation simplifies several features of real administrative data. Names are drawn from small predefined lists, corruption is introduced only among true matched records, and each selected record receives one of three simple changes: a first-name abbreviation, a last-name typo, or a one-day DOB shift. It therefore leaves out missing identifiers, simultaneous errors across several fields, name changes, duplicate individuals, and many other sources of linkage uncertainty. The answer key also assumes that the 100 designated pairs are correct and that all other cross-file pairs are non-matches. If those assumptions were wrong, the estimated weights, threshold performance, and final quality metrics would also be wrong. No generated individual-level records are posted separately.
